조코딩 · 바이브 코딩 1인 창업 부트캠프 (5주 · 영상 11편 기준)

코딩 한 줄 몰라도
돈 버는 서비스 만들기

1페이지는 다섯 살에게 설명하듯, 2페이지는 하나도 빠뜨리지 않고, 3페이지는 당신 환경에 바로 꽂아서.

이 강의를 한 문장으로 줄이면 이렇다 — "웹사이트를 만들어서, 인터넷에 올리고, 거기에 돈 받는 구멍을 뚫는다." 그리고 그 만드는 일은 이제 사람이 안 한다. AI한테 말로 시킨다.

그림 1인터넷 서비스는 사실 식당이다

다섯 살 설명

식당에 가면 두 군데가 있어. 손님이 앉는 홀이랑 요리하는 주방.

홀은 예쁘게 꾸며놨지? 메뉴판도 있고 의자도 있고. 손님이 "김밥 주세요" 하면 주방으로 주문이 들어가. 주방에는 재료 창고가 있고, 거기서 김밥을 만들어서 다시 홀로 내보내.

인터넷 서비스도 똑같아. 우리가 보는 화면이 홀이고, 뒤에서 일하는 컴퓨터가 주방이야. 끝이야. 진짜 이게 다야.

진짜 이름 — 홀 = 프론트엔드(클라이언트) · 주방 = 백엔드(서버) · 재료 창고 = 데이터베이스

그림 2화면은 세 가지로 만든다

다섯 살 설명

HTML은 뼈대야. 사람 몸으로 치면 뼈. "여기 제목, 여기 글자 넣는 칸, 여기 버튼" 하고 자리를 잡는 거지.

CSS는 옷이야. 뼈만 있으면 무섭잖아. 초록색으로 칠하고, 글씨 크게 하고, 모서리 둥글게 하고.

자바스크립트는 신경이야. 버튼을 눌렀을 때 "삐빅! 비밀번호 틀렸어요"가 튀어나오게 하는 거. 움직이는 건 전부 얘가 한다.

중요 — 문법은 몰라도 된다. "HTML은 뼈대, CSS는 옷, JS는 신경" 이 역할만 알면, 나머지는 AI에게 "HTML로 만들어줘" 하면 끝난다.

진짜로 이게 다다

강의에서 처음 하는 실습이 이거다. 메모장을 열고 딱 이만큼 친다.

<h1>안녕</h1>

저장하고 크롬으로 열면 "안녕"이 뜬다. 축하한다, 방금 웹 개발을 했다. 그다음부터는 ChatGPT에 "HTML 코드로 로또 번호 추천 사이트 만들어줘"라고 치고, 나온 코드를 붙여넣으면 된다. 조코딩 표현으로 "뭐 해줘 딸깍, 뭐 해줘 딸깍".

그림 3내 컴퓨터 안에 있으면 아무도 못 본다

다섯 살 설명

냉장고에 그림을 붙여놨어. 예쁘지? 그런데 친구들은 못 봐. 우리 집에 와야 볼 수 있잖아.

방법이 둘이야. 하나, 우리 집 문을 24시간 열어놓고 "다들 와서 봐!" 하는 거. 근데 내가 잠들거나 이사 가면 못 봐. 도둑도 들어올 수 있고.

둘, 동네 미술관에 걸어놓는 거. 미술관은 24시간 불이 켜져 있고, 경비 아저씨도 있고, 전 세계 사람이 와서 볼 수 있어. 이게 훨씬 낫지.

진짜 이름 — 미술관 = 클라우드 서버 · 그림 걸기 = 배포(deploy). 강의에서 쓰는 미술관은 Cloudflare Pages인데, 놀랍게도 공짜다. 전 세계가 다 들어와도 공짜.

그림 4남의 주방을 빌려 쓴다 — API

다섯 살 설명

초밥을 팔고 싶은데 나는 초밥을 못 만들어. 근데 옆집에 초밥 장인이 있어.

그래서 옆집에 주문서를 넣어. "연어초밥 2개요." 그러면 옆집이 만들어서 창구로 내줘. 나는 그걸 받아서 내 손님한테 주면 돼. 내 가게에서 파는 것처럼.

이 주문서 규칙이 바로 API야. "이 주소로, 이렇게 적어서 보내면, 이런 모양으로 돌려준다"는 약속.

실전 — 우리가 AI 서비스를 만들 때 AI를 직접 만들지 않는다. OpenAI라는 옆집에 주문서(API)를 넣고 결과만 받아온다. 요즘 "대단한 AI 스타트업"의 상당수가 이 구조다. 강의에서는 이걸 대놓고 "래퍼(wrapper)"라고 부른다.

그림 5열쇠는 손님에게 주지 않는다

다섯 살 설명

옆집 초밥 장인이 나한테 회원카드를 줬어. 이 카드를 보여주면 초밥을 만들어주는데, 값은 나한테 청구돼.

그런데 이 카드를 홀에 붙여놨어. 손님들이 다 볼 수 있게. 어떻게 될까? 손님들이 그 번호를 적어가서 마음대로 초밥을 시켜 먹고, 돈은 내가 다 낸다.

그래서 카드는 주방 서랍에 넣고 잠근다. 손님은 나한테 주문하고, 카드는 내가 주방에서 몰래 쓴다.

진짜 이름 — 회원카드 = API 키. 주방 서랍 = 백엔드(Cloudflare Workers). 강의에서 백엔드를 굳이 만드는 가장 큰 이유가 정확히 이것이다.

그림 6주방은 빌려 쓰는 게 싸다 — 서버리스

다섯 살 설명

차가 필요해. 근데 일주일에 두 번만 타. 차를 사면 안 탈 때도 주차비, 보험료가 계속 나가. 택시를 타면 탈 때만 돈을 낸다.

주방도 똑같아. 손님이 하루에 열 번 오는데 주방을 24시간 켜둘 필요가 없잖아. 주문이 들어올 때만 잠깐 켰다 끄는 주방이 있으면 훨씬 싸겠지.

진짜 이름 — 택시 같은 주방 = 서버리스. "서버가 없다"는 뜻이 아니라 쓴 만큼만 낸다는 뜻이다. 강의에서 쓰는 건 Cloudflare Workers / Pages Functions.

그림 7다시 오는 아이들이 몇 명이냐

다섯 살 설명

놀이터를 새로 만들었어. 첫날에 100명이 왔어! 신난다.

그런데 한 달 뒤에 몇 명이 아직도 오고 있냐가 진짜 중요해. 0명이면 그 놀이터는 재미없는 거야. 20명이 계속 오면 괜찮은 놀이터, 40명이면 엄청난 놀이터, 70명이면 세상을 바꾸는 놀이터야.

0명으로 쭉 떨어지지 않고 어느 선에서 딱 멈춰서 평평해지면, 그때 "아, 이 놀이터는 되는구나" 하고 아는 거야.

진짜 이름 — 다시 오는 비율 = 리텐션 · 평평해지는 것 = PMF 달성. 실측값: ChatGPT 68%, Gemini 57%, Sora 8% 미만.

그림 85주 동안 뭘 하는가

마지막그래서 뭘 하면 되나

  1. 큰 그림만 외운다. 홀(프론트엔드) / 주방(백엔드) / 창고(DB). 이것만 알면 AI가 무슨 말을 하는지 알아듣는다.
  2. 세팅을 한 번만 제대로 한다. 개발 환경 + AI + 코드 저장소 + 배포처를 한 번 연결해두면, 그다음부터는 진짜로 "해줘 딸깍"만 남는다.
  3. 작게 내놓고 숫자를 본다. 완벽하게 만들지 말고 대충 내놓고, 사람들이 다시 오는지 본다. 안 오면 버리고 다음 걸 만든다.

조코딩 본인의 정리 — "AI 시대 핵심은 세팅하는 걸 알려주는 것." 그다음은 몰라도 물어보면 AI가 다 알려준다.

여기서부터는 빠뜨리지 않고 전부 적는다. 도구 이름, 왜 그 도구인지, 비용이 얼마인지, 무료 한도가 어디까지인지, 어떤 순서로 연결하는지.

이 교재의 출처와 한계 플레이리스트 21편 중 공개된 11편의 자막 전문을 기준으로 작성했다. 나머지 10편은 멤버십 전용이라 접근할 수 없었다(도메인·SEO, 바이럴 구조, 바이브 디자인, Polar 결제 구현, 이메일·다국어, 회원가입 구현, 구독 결제 구현, 퍼널 설계, 페이지 속도, 퍼포먼스 마케팅). 그 10편의 주제는 공개편에서 언급된 범위 안에서만 서술했고, 실습 절차는 다루지 않는다.

1-2. 개발 환경 — 처음엔 메모장

회원가입과 설치가 가장 큰 장벽이므로 1일차는 메모장 + ChatGPT로만 진행한다.

  • Windows: 우클릭 → 새로 만들기 → 텍스트 문서 → 이름을 index.html 로. 확장자가 안 보이면 탐색기 → 옵션 → 보기 → "알려진 파일 형식의 파일 확장명 숨기기" 해제
  • Mac: 메모(Notes) 아님. 텍스트 편집기(TextEdit) → 포맷을 일반 텍스트로 → index.html 저장
  • 저장은 Ctrl+S. 크롬으로 열면 실행된다
HTML을 이해하면 생기는 부수 효과 아무 웹페이지에서 우클릭 → 검사 → 요소를 골라 텍스트나 이미지 주소를 바꾸면 화면이 바뀐다. 이건 내 브라우저의 프론트엔드만 바뀐 것이고 백엔드는 그대로다. 다른 사람에겐 아무 영향이 없다. "해킹"이 아니라 프론트엔드와 백엔드의 차이를 몸으로 이해하는 실습이다.

1-3. 배포 — Cloudflare Pages

내 컴퓨터의 C:\...\index.html 은 나만 볼 수 있다. 선택지는 둘이다.

  1. 내 컴퓨터를 서버로 — IP를 열어 남이 들어오게 함. 컴퓨터를 24시간 켜둬야 하고 보안 위험. 요즘 안 쓴다.
  2. 클라우드 서버를 빌림 — 데이터센터의 컴퓨터에 파일을 올려둔다. 이 행위가 배포(deploy).
왜 하필 Cloudflare Pages인가 무료 플랜에서 Unlimited Bandwidth. 전 세계 인구가 다 들어와도 트래픽 비용이 0이다. 이런 조건을 주는 곳이 여기밖에 없다. AWS·Azure·GCP·Netlify·Vercel 다 대안이지만 이 조건에서는 Cloudflare가 유일하다.
가입 후 반드시 주의 Workers & Pages → Create application 에서 기본 화면은 Workers다. 여기 올리면 사용량 과금이 붙는다. 아래로 내려 "Looking for Pages?" 의 Get started를 눌러야 무료 정적 배포다. 그리고 업로드는 파일이 아니라 폴더를, 파일명은 반드시 index.html.

1-4. 고급 개발 세팅 — 이 세팅이 이 강의의 절반

세팅 상세

  • Firebase Studio — 클라우드 IDE. New Workspace → 첫 주는 Simple HTML. 컴퓨터 사양·용량과 무관. 다른 노트북에서 접속해도 그대로.
  • 대체제 — 서비스가 종료될 경우 GitHub Codespaces. 로컬을 원하면 VS Code. 어느 쪽이든 결과는 같다.
  • AI CLI 설치 — 터미널(New Terminal)에 각 공식 사이트의 설치 명령을 붙여넣고 엔터, 그다음 로그인. 실행 명령을 잊었으면 AI에게 물어보면 알려준다.
  • 어떤 AI를 쓰나 — 영상 기준: 성능은 Claude Code가 가장 좋고, 무료 제공량은 Gemini CLI가 가장 많아 강의는 Gemini로 진행. Codex는 ChatGPT 구독 연계. 고정하지 말고 그때그때 가장 좋은 걸 쓰라는 것이 강의의 입장.
  • 템플릿 정리 — README.md, GEMINI.md 등 기본 생성 파일은 지워도 된다. HTML·CSS·JS만 남기면 충분하다.
  • 승인 모드 — AI가 작업 승인을 물을 때 Allow for this session을 고르면 그 세션 동안 자동 진행된다.
  • 브랜치 — main에 배포하면 실서비스에 반영, 다른 브랜치는 개발용 사이트로 배포된다. 이것도 말로 시키면 된다.

1-5. 외부 서비스 붙이기 — 백엔드를 안 만들고 기능 얻기

서비스얻는 기능직접 만들면
Formspree문의하기 폼 → 내 이메일로 전송백엔드 서버 + 저장 로직 필요
Disqus댓글 기능DB + 인증 + 스팸 필터 필요
Teachable Machine브라우저에서 도는 이미지 분류 AI모델 학습 + 서빙 인프라 필요
붙이는 법은 셋 다 똑같다 공식 문서의 예시 코드를 그대로 복사해서 AI에게 붙여넣고 "이거 참고해서 붙여줘"라고 하면 된다. 문서를 사람이 읽을 필요가 없다. URL만 줘도 AI가 읽고 구현한다.

체감 근거 — 크몽에서 "홈페이지 제작 + 반응형 + 서브페이지 + 문의하기"가 110만 원짜리 작업이다. 이 중 문의하기를 Formspree로 몇 분 만에 끝냈다.

3주차React · 서버리스 · AI API · 글로벌 결제

3-1. 돈 되는 아이디어를 고르는 공식

"이미 돈이 도는 시장"에서 시작한다. 사람들이 이미 지불하고 있다는 게 증명된 시장이면 검증 부담이 줄어든다.

조코딩이 고른 실제 예시 — 본인이 구글 CEO 인터뷰를 앞두고 퍼스널 스타일리스트 컨설팅을 실제로 돈 주고 받았다. 시장 가격은 온라인 코스 13.2만 원, 프리미엄 컨설팅 50만~880만 원.

세 개의 렌즈

  1. "Your margin is my opportunity" (제프 베조스) — 비싼 시장 = 기회
  2. "왜 비싸지?" → "사람이 들어가서 비싸구나" → AI로 단가를 무너뜨린다
  3. "Paint it pink for women" — 같은 기능도 타겟에 따라 매출 규모가 다르다. 여성향 소비 시장의 지불 의향이 높다는 관찰

3-2. React를 왜 쓰나 (안 써도 된다)

  • HTML·CSS·JS만으로 전부 만들 수 있다. React는 파일과 중복 코드가 많아지는 문제를 컴포넌트로 압축하는 도구일 뿐이다.
  • 라이브러리 = 내가 주도권을 갖고 import해서 갖다 쓰는 것. 프레임워크 = 규칙이 정해져 있어 그 규칙대로 쓰는 것.
  • 선택 기준은 "순위가 높은 것". 자료가 많다 = AI가 많이 학습했다 = AI가 더 잘한다. 그래서 TypeScript + React.
  • Vite — React 문법을 브라우저가 이해하는 HTML/CSS/JS로 변환(빌드)해주는 도구.
  • Next.js와의 차이 — React는 프론트엔드 전용. Next.js는 React 위에 서버 기능까지 얹은 메타 프레임워크. 서버 연산이 붙으면 돈이 든다. 정적 배포는 캐시 전달만 하므로 공짜. 이 강의가 React+Vite를 쓰는 이유가 이것이다.

3-3. 서버리스 — Cloudflare Pages Functions

백엔드 서버를 통째로 빌리면 요청이 없어도 24시간 요금이 나간다. 요청이 올 때만 켜졌다 꺼지는 종량제 백엔드가 서버리스다. (AWS Lambda, Cloud Run, Edge Functions, Cloudflare Workers)

백엔드가 반드시 필요한 이유는 단 하나 API 키를 프론트엔드에 내려보내면 안 된다. 사용자 브라우저로 간 키는 그대로 털리고, 카드가 등록돼 있으면 요금이 빠져나간다. 그래서 키는 Workers에 환경변수(Secret)로 등록하고 백엔드에서만 호출한다.

이 구성(정적 프론트 + 서버리스 API + 외부 서비스)을 JAMstack이라 부른다.

3-4. OpenAI API 실전

절차

  1. platform.openai.com 가입 → 프로젝트 생성 → API 키 발급 (노출 금지)
  2. 크레딧 충전 — 여기서 처음으로 돈이 나간다. 카드 등록 필요
  3. 대시보드 Playground에서 먼저 실험 — Developer message(역할 부여) + User message로 결과 확인
  4. 잘 되면 ⋯ → Code 로 최신 코드를 뽑아 AI에게 붙여넣는다
놓치면 반드시 막히는 지점 AI가 짜주는 OpenAI 코드는 학습 시점이 오래돼서 구버전(chat.completions)인 경우가 많다. 최신은 v1/responses. 반드시 Playground에서 현재 코드를 복사해 AI에게 주고 "이거 참고해서 최신 코드로 업데이트해"라고 해야 한다.

원가 계산 (강의 실측, GPT 5.2 기준)

입력 100만 토큰 $1.75 / 출력 100만 토큰 $14. 스타일 리포트 1건 = 입력 109토큰 + 출력 177토큰 ≈ $0.02 ≈ 29원.

즉 리포트 1건당 원가 29원. 3.99달러에 팔면 마진 구조가 즉시 계산된다. 어려운 작업이 아니면 mini 계열 경량 모델로 더 낮출 수 있다.

이미지 API 절약 트릭

이미지는 장당 과금이다. 프롬프트에 "3×3 그리드로"를 넣으면 같은 값에 9장을 얻는다. 얼굴이 바뀌는 걸 막으려면 "첨부한 사람의 얼굴은 절대 바꾸지 말고 헤어스타일만 바꿔"를 명시한다.

대안

OpenAI 외에 Google(나노바나나 계열), Replicate(오픈소스 모델을 API로 제공).

3-5. 글로벌 결제 — Polar (MOR)

한국에서는 Stripe를 직접 쓸 수 없다(절차가 매우 복잡). 그래서 MOR인 Polar를 쓴다. 수수료가 더 비싸고 판매 가능 품목이 소프트웨어/SaaS·디지털 상품·프리미엄 콘텐츠 접근권으로 제한된다. 확장을 원하면 5주차의 미국 법인 + Stripe로 간다.

강의 시연에서 결제 연동 후 실제로 $31.92가 발생했다. (구체적 구현 절차는 멤버십 편)

4주차DB · 스토리지 · 회원 · 구독

4-1. 데이터베이스

Supabase (선택 이유 = 무료 한도)

  • 무제한 API 요청 무료
  • MAU 5만 명까지 무료
  • 트래픽 급증 시 자동 스케일
  • Auth 제품 내장 → 회원가입·소셜 로그인을 바로 붙일 수 있다
  • 단점: 무료 프로젝트는 일주일 미사용 시 정지 — 홈페이지에서 다시 켜야 함. 무료는 프로젝트 2개까지
  • 보안 경고: 프로젝트 생성 시 정한 DB 비밀번호가 유출되면 회원정보 유출 뉴스의 주인공이 된다. 반드시 강한 비밀번호로, 안전한 곳에 보관
  • Region: 글로벌 서비스면 그대로, 한국 중심이면 아시아·태평양

4-2. 스토리지 — Cloudflare R2

사진·영상을 DB에 넣으면 용량이 폭발한다. 정석은 스토리지에 올리고 DB에는 주소만 저장하는 것. 개발자용 구글 드라이브라고 보면 된다.

왜 R2인가 이그레스(송신) 비용이 없다. AWS S3는 이그레스가 꽤 비싸다. 무료 10GB/월. Supabase에도 스토리지가 있지만 더 싼 쪽을 쓴다는 원칙에 따라 R2.

4-3. 구독 전환 — 왜 단건 결제를 버리는가

3주차까지는 로그인 없이 단건 결제였다. 문제는 매번 결제가 진입 장벽이 되어 전환이 안 나오고, 반복 매출·리텐션이 생기지 않는다는 것. 그래서 4주차에 구조를 바꾼다.

  • 정보를 DB에 한 번만 등록 → 사진은 스토리지에
  • 구독 등록 → 매달 자동 결제
  • 크론잡으로 매일 정해진 시각(예: 아침 6시)에 결과 발송
  • 무료 체험 — 카드를 걸어두면 며칠 뒤 자동 결제. 전환율을 위한 표준 장치

이 주차에는 결제를 유도하는 심리적 장치와 퍼널 분석·페이지 속도 최적화도 다뤄지지만, 해당 회차는 멤버십 전용이다.

5주차앱 · 미국 법인 · 엑싯

5-1. 앱 만드는 네 가지 방법

방식장점단점
네이티브 (Android/iOS 각각)성능 최고, OS 기능 전부 사용두 번 만들어야 함, 필요 지식 많음
크로스 플랫폼 (React Native/Expo, Flutter)하나로 둘 다. 빠름OS 최신 기능은 대응까지 대기
하이브리드 (웹뷰로 감싸기)기존 웹사이트를 그대로. 심사 없이 웹만 고치면 반영성능 낮음. 단순 재포장은 앱스토어 거절
PWA껍데기조차 없음. 아이콘으로 설치되는 웹엄밀히는 앱이 아님

강의 선택 = Expo

  • React Native를 한 번 더 감싼 것. EAS로 클라우드 빌드 → 내 컴퓨터 사양 무관, Android Studio·Xcode 불필요
  • Expo Go 앱을 폰에 깔면 별도 빌드 없이 실기기에서 바로 테스트
  • Development Build는 네이티브 기능을 더 쓸 때 선택
  • 클라우드 IDE에서는 npx expo login 후 npx expo start --tunnel
  • 구조는 웹과 완전히 동일 — 앱이 클라이언트, 백엔드는 그대로 Workers. 버전 불일치 같은 에러는 스크린샷을 AI에 붙여넣으면 원인 파악하고 고친다
  • 보안: 백엔드 URL이 열려 있으면 남이 만든 앱도 요청을 날릴 수 있다. 로그인 또는 결제로 막아야 한다
  • RevenueCat — Android·iOS·웹 구독을 통합 관리. Stripe와 연결 가능
  • 등록비: Google Play $25(1회), Apple $99(연간). 콘솔 등록 절차는 화면을 캡처해서 AI에게 물어가며 진행
  • 국내 대안: Apps in Toss 미니앱 — 개발자 등록 없이 토스 앱 안에 출시

5-2. 미국 법인 — Stripe Atlas

왜 세우나

  1. Stripe — 글로벌 결제 표준. OpenAI·Netflix·Shopify·Notion·Slack이 다 쓴다. 수수료 2.9% + 30¢로 MOR보다 훨씬 싸고, 판매 품목 제한이 없다. South Korea 항목이 별도로 있어 카카오페이·네이버페이·페이코·삼성페이도 받을 수 있다
  2. 델라웨어 C Corporation — 글로벌 투자·인수의 디폴트 옵션. VC 투자, M&A, 스톡옵션 설계, IPO 구조가 표준화되어 있다

C Corp vs LLC

C Corp = 법인 사업자 (기본값, 투자·엑싯 지향). LLC = 개인 사업자 느낌 (내수 소규모, 세무 단순).

세금

3-2예제 A — 영상 강의 교재 생성기 (가장 적합)

왜 이게 1순위인가

당신은 지금 이 작업을 수동으로 하고 있다. yt-dlp로 자막을 받고, whisper로 전사하고, 정리해서 HTML 교재를 만들고, GitHub Pages에 배포한다. 파이프라인이 이미 검증됐다. 조코딩 3주차 구조(프론트 + 서버리스 + AI API + 결제)를 그대로 씌우면 그게 곧 제품이다.

3주차의 아이디어 렌즈로 검산해도 통과한다 — 이미 돈이 도는 시장인가? 강의 요약·노트 서비스는 유료 시장이 존재한다. 왜 비싼가? 사람이 보고 정리해서 비싸다. AI로 단가를 무너뜨릴 수 있는가? 원가는 API 호출 몇 십 원이다.

단계별 실행

  1. MVP (저장 없음, 로그인 없음) — URL 입력 → 결제 → 교재 HTML 반환. DB 불필요. 조코딩 3주차와 같은 형태
  2. 원가 계산부터 — 30분 영상 자막 ≈ 2~3만 자. 입력 토큰이 크므로 출력 단가보다 입력 단가가 중요하다. 반드시 Playground에서 실제 자막을 넣어 토큰 수를 재고 판매가를 정한다
  3. 자막 추출은 백엔드에서 — yt-dlp를 서버리스에서 돌리기 어려우므로, ① 사용자가 자막을 붙여넣게 하거나 ② 스크래핑/전사 API 레이어를 쓴다. 1단계는 ①로 시작하면 인프라 비용이 0이다
  4. 검증 지표 — 리텐션이 아니라 재구매율을 본다. 1회용이면 0%로 수렴한다(동물상 테스트 0.5% 사례). 재구매가 안 나오면 구독형(채널 구독 → 새 영상 자동 교재화)으로 전환한다 — 이게 4주차가 단건에서 구독으로 넘어간 이유와 정확히 같다

(1p 쉬운 설명 / 2p 상세 / 3p 적용 예제)를 생성하는 웹서비스를 만들 거야.

3-3예제 B — 무료 트래픽 사이트로 애드센스 먼저 뚫기

목적은 수익이 아니라 자격 획득이다. 애드센스 심사는 며칠~4주가 걸리고, 한 번 통과하면 계정에 붙는다. 진짜 제품이 준비되기 전에 미리 뚫어두는 것이 시간 절약이다.

당신에게 유리한 조건

  • 이미 kooys2013.github.io/pages/ 에 여러 개의 콘텐츠 페이지가 배포돼 있다 — 심사에서 요구하는 "콘텐츠 분량"의 원재료가 이미 있다
  • 조코딩의 우회법(블로그 10편 채우고 통과 후 제거)을 쓸 필요 없이, 정식으로 통과 가능한 분량을 이미 만들 수 있다

순서

  1. 독립 도메인 또는 Pages 하위 경로로 콘텐츠 허브 하나 구성
  2. 개인정보처리방침 · 소개 페이지 · 연락처 추가 (AI에게 시키면 한 번에)
  3. AdSense 사이트 등록 → 소유권 확인 <meta> 삽입 → 검토 요청
  4. 거절되면 거절 사유 원문 + 공식 가이드 링크를 AI에 던져서 보완 후 재요청

기대 수익은 초기에 크지 않다. 이건 자격 획득 트랙이지 수익 트랙이 아니다. 수익은 예제 A의 결제에서 나온다.
