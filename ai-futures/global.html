해외판 · 조코딩 선물거래 강의의 대응 커리큘럼

검증부터 시작하는
자동매매 커리큘럼

조코딩 강의가 13강에 놓은 것을 이 커리큘럼들은 1강에 놓는다. 그 순서 하나가 전부를 바꾼다. 전부 무료이고 오픈소스다.

해외에 더 화려한 강의가 있는 게 아니다. 순서가 다른 강의가 있다. 조코딩은 만드는 법을 가르치고, 이쪽은 그게 진짜인지 확인하는 법을 가르친다. 후자가 훨씬 어렵고, 훨씬 중요하다.

그림 1시험을 먼저 볼 것인가, 모의고사를 먼저 볼 것인가

다섯 살 설명

내일 진짜 시험이야. 근데 공부를 했는지 안 했는지 모르겠어.

방법 1 — 그냥 시험을 봐. 점수가 나오면 그때 알겠지. 근데 시험은 한 번뿐이고, 망하면 끝이야.

방법 2 — 옛날 시험지를 잔뜩 가져와서 모의고사부터 봐. 여기서 60점이면 진짜 시험도 60점쯤 나오겠지. 망해도 아무도 안 다쳐.

돈이 걸린 일에서는 당연히 방법 2야. 그런데 놀랍게도 대부분의 자동매매 강의는 방법 1을 가르친다.

진짜 이름 — 옛날 시험지로 미리 풀어보기 = 백테스트. 조코딩 강의는 실거래가 3강, 백테스트가 13강이다. 시험을 먼저 보고 모의고사를 나중에 본다.

그림 2모의고사 답을 외우면 안 된다

다섯 살 설명

모의고사를 100번 풀었어. 이제 100점이야! 신난다.

그런데 답을 외운 거야. 문제를 이해한 게 아니라. 진짜 시험은 다른 문제가 나오니까 0점이 나와.

그래서 똑똑한 방법이 있어. 모의고사를 반으로 갈라. 앞쪽으로만 공부하고, 뒤쪽은 절대 안 봐. 그리고 뒤쪽으로 시험을 봐. 여기서도 점수가 나오면 진짜로 아는 거야.

진짜 이름 — 답 외우기 = 과최적화(overfitting) · 뒤쪽으로 시험보기 = 아웃오브샘플 검증 · 이걸 여러 구간으로 반복 = 워크포워드 분석

그림 3LLM은 이미 답지를 봤다 — 가장 중요한 그림

다섯 살 설명

2024년 1월 시험지를 주면서 "이거 풀어봐" 했어.

그런데 이 친구는 2026년까지의 신문을 전부 읽은 상태야. 2024년 2월에 무슨 일이 있었는지 이미 알고 있어.

그러니까 시험을 아주 잘 봐. 그런데 그건 실력이 아니야. 내일 일어날 일은 신문에 없으니까, 진짜 시험에서는 못 맞춰.

진짜 이름 — 룩어헤드 편향(look-ahead bias). 이건 코드로 막을 수 있는 종류의 버그가 아니다. 모델의 학습 데이터 안에 미래가 들어 있다.
이 한 가지가 조코딩 13강의 결론을 무력화한다 GPT-4.5o에게 2026년 1월 1~3일 비트코인 차트를 주고 "롱이냐 숏이냐" 물었을 때 +9.71%가 나왔다 해도, 모델이 그 기간의 결과를 이미 알고 있었을 가능성을 배제할 방법이 없다. 재현조차 안 되므로 분산도 측정할 수 없다. 이 두 가지가 겹치면 그 숫자로는 아무것도 주장할 수 없다.

마지막세 문장 요약

  1. 순서가 전부다. 리서치 → 백테스트 → 페이퍼 → 실거래. 건너뛰면 검증이 아니라 도박이다.
  2. 한 번 잘 나온 결과는 증거가 아니다. 여러 구간에서 반복해서 살아남아야 한다.
  3. LLM에게 과거를 물어보면 컨닝이 된다. LLM은 신호 생성보다 컨텍스트 요약에 쓰는 게 안전하다.

아래 셋이 해외 표준이다. 전부 무료·오픈소스이고, 조코딩 강의가 다루지 않는 검증 레이어를 기본으로 갖고 있다. 셋 다 배울 필요는 없다 — 목적에 따라 하나를 고른다.

2검증 개념 사전

조코딩 강의에 한 번도 등장하지 않는 용어들이다. 그리고 이것들이 "돈을 버는가"를 판정하는 실제 도구다.

인샘플 / 아웃오브샘플 (In-sample / Out-of-sample)
전략을 만들 때 본 데이터 / 만들 때 보지 않은 데이터. 성능 주장은 반드시 아웃오브샘플 기준이어야 한다.
워크포워드 분석 (Walk-Forward Analysis)
학습 구간에서 최적화하고 바로 다음의 보지 않은 구간에서 검증하는 것을 구간을 밀어가며 반복. 단일 검증 구간에서 오는 거짓 확신을 막는다. 전략이 서로 다른 시장 국면에서 반복적으로 스스로를 증명해야 한다.
과최적화 (Overfitting)
과거 데이터에 지나치게 맞춰져서 백테스트는 좋은데 실전에서 무너지는 상태. 패턴이 아니라 노이즈를 외운 것.
룩어헤드 편향 (Look-ahead bias)
판단 시점에 알 수 없었던 정보가 새어든 것. LLM에서는 모델 학습 데이터에 미래가 포함되므로 코드로 막을 수 없다. Look-Ahead-Bench(arXiv 2601.13770)가 이를 표준 벤치마크로 정식화했다.
데이터 리키지 (Data leakage)
정규화·피처 생성 과정에서 전체 기간 통계를 써버리는 등, 미래 정보가 간접적으로 새는 것.
PBO (Probability of Backtest Overfitting)
이 백테스트 결과가 과최적화의 산물일 확률. 여러 전략 후보를 비교할 때 선택 행위 자체가 만드는 편향을 정량화한다.
CPCV (Combinatorial Purged Cross-Validation)
시계열용 교차검증. 학습·검증 구간 사이를 purge/embargo로 격리해 인접 구간의 정보 누수를 막는다. López de Prado의 Advances in Financial Machine Learning이 표준 참고서다.
Deflated Sharpe Ratio
여러 번 시도해서 고른 전략의 샤프 비율을 시도 횟수로 할인한 값. 100개를 돌려 최고를 고르면 샤프가 높게 나오는 게 당연하다 — 그 편향을 뺀다.
드라이런 / 페이퍼 트레이딩
실시간 시세로 돌리되 실제 주문은 내지 않는 모드. 백테스트가 못 잡는 지연·API 오류·재접속 문제를 여기서 만난다.
슬리피지 (Slippage)
주문 의도 가격과 실제 체결가의 차이. 시장가 주문이면 반드시 발생한다.
펀딩비 (Funding rate)
무기한 선물에서 8시간마다 롱↔숏 간 정산되는 비용. 포지션을 오래 들고 있으면 누적된다. 조코딩 백테스트에는 반영돼 있지 않다.
기대값 · 손익분기 승률
손익비가 1:1이면 수수료·슬리피지 때문에 승률이 50%를 넘어야 본전이다. MVP의 SL/TP ±0.5%가 정확히 이 구조다.

3Freqtrade 실전 순서

조코딩 커리큘럼과 같은 목표를 안전한 순서로 밟으면 이렇게 된다.

① 설치 · 전략 생성

# 전략 템플릿 생성
freqtrade new-strategy --strategy MyStrategy

# 과거 데이터 다운로드 (충분히 길게 — 여러 시장 국면 포함)
freqtrade download-data --exchange binance \
  --pairs BTC/USDT:USDT --timeframes 15m 1h 4h \
  --timerange 20240101-20260801

② 백테스트 — 실거래 전에

freqtrade backtesting --strategy MyStrategy \
  --timerange 20240101-20251231 \
  --fee 0.0005 \
  --timeframe 15m

--fee는 조코딩이 쓴 것과 같은 바이낸스 테이커 0.05%다. 슬리피지는 설정에서 별도 모델링한다.

③ 워크포워드 — 여기가 조코딩에 없는 단계

freqtrade hyperopt --strategy MyStrategy \
  --hyperopt-loss SharpeHyperOptLoss \
  --timerange 20240101-20250630 --epochs 200

# 최적화에 쓰지 않은 구간에서만 검증
freqtrade backtesting --strategy MyStrategy \
  --timerange 20250701-20260801
판정 기준 아웃오브샘플에서 샤프가 40% 넘게 떨어지거나 최대낙폭이 두 배가 되면 과최적화로 본다. 이때 해야 할 일은 파라미터를 다시 만지는 게 아니라 전략을 버리는 것이다.

④ 페이퍼 트레이딩 — 기본값

// config.json
{
  "dry_run": true,          // 기본값. 실거래 전 최소 수 주 유지
  "dry_run_wallet": 1000,
  "stoploss": -0.02,
  "max_open_trades": 3
}
freqtrade trade --config config.json --strategy MyStrategy

⑤ 실거래 — 마지막에, 격리된 자본으로

// dry_run을 false로 바꾸는 것은 명시적 결정이어야 한다
{ "dry_run": false }

4LLM을 쓴다면 — 안전한 자리

LLM 사용처실패했을 때판정
포지션 크기·레버리지 결정자본에 직결. 되돌릴 수 없음쓰지 말 것
승률 p 추정 → 켈리 입력과대추정 시 over-betting → 파산 확률 급증쓰지 말 것
진입 방향(롱/숏) 단독 결정룩어헤드로 백테스트 검증 불가검증 불가 · 비권장
뉴스·공시를 레짐 태그로 분류부울/카테고리 하나가 틀림. 격리 가능검증 가능
규칙 기반 신호에 필터로 부착거래를 안 하게 될 뿐. 하방이 제한됨검증 가능
전략 코드 작성 보조사람이 리뷰. 백테스트가 잡음권장
결과 리포트 해설·요약글이 틀릴 뿐권장
경계선 한 문장 LLM이 "얼마를 걸지"를 정하면 실패가 자본에 직결되고, "지금이 어떤 국면인지"만 태그하면 실패가 값 하나로 격리된다. 이 선을 넘지 않는 한 LLM은 유용하다.

현재 업계 상태에 대한 정리 — 완전 자율 LLM 트레이딩은 미해결 문제로 남아 있고, 하이브리드(AI + 규칙 기반)가 주류다. 또한 Princeton 연구는 AI 트레이딩 에이전트에 거짓 기억을 심어 결제를 공격자 지갑으로 유도할 수 있음을 보였다 — 9-4의 "과거 거래 내역을 프롬프트에 주입하는" 설계가 정확히 그 공격면이다.

당신은 이미 CPCV · PBO · Deflated Sharpe · 켈리 · 킬스위치 · fail-closed 게이트를 쓰는 실가동 시스템을 운영한다. 즉 이 페이지의 내용을 이미 상당 부분 실천하고 있다. 아래는 그 관점에서의 정밀 비교와, 실제로 가져올 것 세 가지다.

결론이 명확하다 당신의 시스템은 이미 Freqtrade·QuantConnect와 같은 열에 있거나 그 이상이다. 조코딩 강의를 도입할 이유는 없고, 해외 도구를 통째로 도입할 이유도 크지 않다. 가져올 것은 개별 요소 몇 개뿐이다.

3-2실제로 가져올 것 — 3가지

① 룩어헤드 편향 항목을 LLM 사용처까지 확장

당신의 누적 교훈에는 이미 "통계 검정만으로 처치 채택 금지 — 룩어헤드를 먼저 뒤진다"가 있고, 실제로 룩어헤드 산출물이 부트스트랩 CI를 통과했던 사고를 겪었다.

여기에 새로운 축이 하나 추가된다 — 지금까지의 룩어헤드는 데이터 파이프라인에서 왔다. LLM을 쓰는 순간 모델 가중치 자체가 룩어헤드 소스가 된다. 이건 코드 검사로 잡을 수 없다.

추가할 규칙 (제안) WHEN 백테스트 구간이 LLM 학습 컷오프 이전 THEN 그 LLM의 판단을 신호로 쓰지 않는다. 컷오프 이후 구간에서만 forward test로 평가한다.

② "실패가 어디로 흐르는가"로 LLM 사용처를 나누는 기준

2페이지의 표가 실제로 쓸 만한 기준이다. 당신 시스템에 적용하면 이렇게 갈린다.

영역LLM 허용이유
포지션 사이징 · 레버리지 · 진입 판단금지실패가 자본에 직결. 되돌릴 수 없음
레짐 태깅 · 뉴스 플래그조건부부울 값 하나로 격리 가능 · 사후 검증 가능
실험 설계 · 코드 작성 · 리뷰허용사람과 백테스트가 잡음. 이미 하고 있음
리포트 해설 · 회고허용글이 틀릴 뿐

③ 프롬프트 튜닝을 파라미터 최적화로 취급

조코딩 13강의 "프롬프트를 바꿔가며 어떤 게 잘 되는지 테스트해 보라"는 안내는, 통계적으로는 파라미터 그리드 서치와 완전히 동일한 행위다. 그런데 프롬프트는 자연어라서 탐색 공간이 사실상 무한하고, 시도 횟수를 세기도 어렵다.

그래서 더 위험하다 Deflated Sharpe는 시도 횟수로 할인한다. 프롬프트 튜닝은 시도 횟수가 기록되지 않으므로 할인할 수조차 없다. 프롬프트를 고쳤으면 그것도 시도 1회로 카운트하고 로그에 남겨야 한다.

당신 하네스의 llm-eval-suite·confidence-calibration·trajectory-tracker가 이미 이 계열의 도구다. 프롬프트 변경을 실험 이력으로 남기는 규율을 트레이딩 쪽에도 적용하면 된다.

3-3만약 검증 실험을 한다면 — 최소 설계

LLM 판단을 트레이딩에 붙이는 것을 진지하게 평가하려면 이 정도는 되어야 한다.

#설계 항목구체 기준
1포워드 테스트만 인정모델 학습 컷오프 이후 기간. 과거 백테스트는 참고용으로도 쓰지 않음
2캘리브레이션 우선LLM이 말한 p vs 실제 승률의 Brier score. 이걸 통과하기 전엔 사이징에 절대 연결하지 않음
3비결정성 정량화동일 입력 N≥20회 반복 → 판단 일치율. 일치율이 낮으면 신호로 부적격
4대조군 필수같은 기간 Buy&Hold + 기존 규칙 전략. 단독 수익률은 의미 없음
5표본 하한거래 200건 이상, 2개 이상 시장 국면
6비용 전량테이커 수수료 + 슬리피지 + 펀딩비
7노출 하드캡position_size × leverage ≤ 1.0 · 하프 켈리 이하
8자본 격리기존 봇 계좌와 완전 분리. 실계좌 이전에 Testnet 30일
9프롬프트 주입 방어뉴스·과거 거래를 프롬프트에 넣는다면 그건 신뢰 경계다. 외부 텍스트가 주문 파라미터를 바꾸지 못하게 스키마로 강제
10fail-closedLLM 응답 파싱 실패 · 타임아웃 · 스키마 위반 → 진입 안 함. 재시도로 뚫지 않음
9번을 특히 강조한다 조코딩 9-4는 DB의 과거 거래 내역을, 8-2는 SerpAPI로 긁은 뉴스 텍스트를 프롬프트에 넣는다. 둘 다 외부에서 내용을 조작할 수 있는 경로다. Princeton 연구가 보인 "AI 트레이딩 에이전트에 거짓 기억 주입" 공격이 정확히 이 구조를 노린다. 프롬프트에 들어가는 외부 텍스트는 데이터이지 명령이 아니라는 것을 스키마로 강제해야 한다.

3-4한 문단 결론

해외에 "훨씬 우수한 강의"가 있느냐고 물으면, 답은 "더 화려한 건 없고, 순서가 옳은 건 있다"이다. Freqtrade와 QuantConnect는 조코딩이 손으로 만든 것을 전부 갖고 있으면서, 그가 마지막에 붙인 검증을 기본값으로 앞에 놓는다. NautilusTrader는 백테-라이브 정합을 아키텍처로 강제한다.

그리고 당신에게 이 문서의 실제 값은 도구가 아니라 한 가지 개념에 있다 — LLM을 트레이딩에 쓰는 순간 룩어헤드의 출처가 데이터 파이프라인에서 모델 가중치로 옮겨간다. 당신은 파이프라인 룩어헤드는 이미 잡고 있지만, 이 새 축은 기존 방어로 잡히지 않는다.

결론은 단순하다 — LLM은 신호가 아니라 컨텍스트에 쓴다. 얼마를 걸지는 검증된 코드가 정한다.
